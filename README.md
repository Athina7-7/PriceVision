# PriceVision

Application with a separated architecture using frontend (Angular 17) and backend (.NET 10) to register construction projects, generate resource and financial cost predictions, and calculate EVM indicators.

## current state

The app currently works with the following flow:

1. Register project
2. Run predictions per project
3. Generate financial prediction
4. Calculate EVM
5. View recent items and history

A manually entered ProjectId is no longer used as the main flow. A project is first registered and then selected from listings in the Predictions and EVM modules.

## Implemented functionalities

### 1. Project Registration

Allows saving a project with:

- name
- area in m²
- location
- project type
- estimated duration in months
- base costs in COP

Includes:

- required validations in frontend and backend
- persistence in SQLite
- non-blocking warnings based on historical data

### 2. Resource predictions

The system uses ML.NET to estimate:

- quantity of materials
- labor hours

Current characteristics:

- models are trained using synthetic datasets generated by the application
- the user can apply only materials, only labor, or complete the missing model for a project
- a prediction already performed for the same model type is not repeated
- the view displays prediction details and recent items

  
### 3. Financial forecast

In addition to the resource model, the app includes a financial prediction associated with the project.

This prediction considers:

- estimated resources
- stored historical costs
- location-based trends

It displays:

- total estimated cost
- minimum and maximum range
- confidence level as a percentage
- confidence classification (High, Medium, Low)

### 4. EVM

La app calcula indicadores de Earned Value Management:

- `PV`: Planned Value
- `EV`: Earned Value
- `AC`: Actual Cost
- `CPI`: Cost Performance Index
- `SPI`: Schedule Performance Index

Current behavior:

- EVM is calculated per selected project
- requires the project to have both material and labor predictions
- does not allow recalculating EVM if a record already exists for the project
- displays detailed results and recent entries in a dedicated view

### 5. . History and recent

The system exposes and displays:

- project history
- recent predictions
- recent financial predictions
- recent EVM records

Each detail includes project information:

- name
- area
- type
- location
- duration
- base cost

## Persistence

The current database is SQLite and is stored at:

- `backend/PriceVision.Api/pricevision.db`

### Main tables

#### `Projects`

Stores the base project record:

- `Id`
- `Name`
- `AreaM2`
- `Location`
- `Type`
- `DurationMonths`
- `BaseCostCop`
- `CreatedAtUtc`

#### `Predictions`

Save resource predictions:

- `ProjectId`
- `AreaM2`
- `Type`
- `Location`
- `DurationDays`
- `EstimatedMaterialQuantity`
- `EstimatedMaterialCostCop`
- `RequiredLaborHours`
- `PredictedMaterials`
- `PredictedLabor`
- `ModelVersion`
- `CreatedAtUtc`

#### `FinancialPredictions`

Stores the financial prediction per project:

- `ProjectId`
- `EstimatedTotalCostCop`
- `MinimumEstimatedCostCop`
- `MaximumEstimatedCostCop`
- `ConfidencePercentage`
- `ConfidenceLevel`
- `HistoricalAverageCostPerM2`
- `LocationTrendFactor`
- `CreatedAtUtc`

#### `EVM_Records`

Save EVM calculations:

- `ProjectId`
- `PeriodDateUtc`
- `PV`
- `EV`
- `AC`
- `CPI`
- `SPI`
- `CostInterpretation`
- `ScheduleInterpretation`
- `CreatedAtUtc`

## Ejecucion

### Backend

Desde la raiz del repo:

```powershell
dotnet restore backend\PriceVision.Api\PriceVision.Api.csproj
dotnet run --project backend\PriceVision.Api\PriceVision.Api.csproj --launch-profile http
```

URL esperada:

- `http://localhost:5054`

Comprobacion rapida:

```powershell
Invoke-RestMethod -Method Get -Uri "http://localhost:5054/api/health"
```

### Frontend

```powershell
cd frontend\pricevision-ui
npm install
npm start
```

URL esperada:

- `http://localhost:4200`

El frontend usa proxy hacia el backend.

## Despliegue

### Despliegue local de prueba
1. Asegúrate de tener instalados:
   - .NET SDK 10
   - Node.js y npm
2. Desde la raíz del repositorio, restaura y ejecuta el backend:

```powershell
dotnet restore backend\PriceVision.Api\PriceVision.Api.csproj
dotnet run --project backend\PriceVision.Api\PriceVision.Api.csproj --launch-profile http
```

3. En otra terminal, instala y ejecuta el frontend:

```powershell
cd frontend\pricevision-ui
npm install
npm start
```

4. Abre el navegador en `http://localhost:4200` y verifica que el backend responda en `http://localhost:5054/api/health`.

### Preparar el backend para producción
1. Publica el proyecto API:

```powershell
dotnet publish backend\PriceVision.Api\PriceVision.Api.csproj -c Release -o backend\PriceVision.Api\publish
```

2. Copia los archivos generados en `backend\PriceVision.Api\publish` al servidor o servicio donde alojarás la API.
3. Asegúrate de incluir la base de datos SQLite `backend\PriceVision.Api\pricevision.db` y la carpeta `backend\PriceVision.Api\Artifacts` si el backend los necesita en tiempo de ejecución.
4. Ejecuta el binario publicado o configura el servicio de hosting para arrancar la aplicación.

### Preparar el frontend para producción
1. Desde `frontend\pricevision-ui`, construye la aplicación Angular:

```powershell
cd frontend\pricevision-ui
npm install
npm run build -- --configuration production
```

2. El sitio público estará en `frontend\pricevision-ui\dist\pricevision-ui`.
3. Sube esa carpeta a un hosting estático (por ejemplo, Azure Static Web Apps, Netlify, Vercel o un servidor estático propio).

### Conectar frontend y backend en la nube
1. En el hosting del frontend, configura el endpoint del backend público.
2. Si usas un proxy o CORS, asegúrate de permitir el dominio del frontend en el backend.
3. Valida que ambos servicios estén accesibles desde internet y que la aplicación Angular llame correctamente a la API.

## Important functional rules

- a project can be registered without executing predictions immediately
- material and labor predictions can be applied separately or together
- only the missing model is allowed to be executed for a project
- the financial prediction is associated with the project
- EVM can only be executed once per project
- the history shows prediction, financial prediction, and EVM events
- Historical validations

When registering a project, the backend may show non-blocking warnings if it detects inconsistencies compared to stored historical data.

Examples:

- extremely low or high base cost per m²
- inconsistent duration for the project type

These warnings:

- do not block registration
- are calculated in the backend
- are visually displayed in Angular
  
  ## Technical notes
- material and labor models use synthetic datasets at this stage
- the current financial prediction is a calculation service, not an independent ML model
- model artifacts are stored in backend/PriceVision.Api/Artifacts
- if you change endpoints or schema, restart the backend so the app reflects the changes

## Automated tests

The project includes a suite of 22 integration tests that cover the 7 user stories of the test plan. The tests run the server in memory without needing the backend to be running separately. This code is located in the Test branch.

## Run tests

From the root of the repository:

dotnet test backend/PriceVision.slnx
Expected result:

Test summary: total: 22; failed: 0; passed: 22; skipped: 0

View detailed results

To see the name and status of each individual test case:

dotnet test backend/PriceVision.slnx --verbosity normal
View results in HTML

To generate an exportable report:

dotnet test backend/PriceVision.slnx --logger "html;LogFileName=results.html"
The file is generated at:
tests/PriceVision.Tests/TestResults/results.html

Open it in any browser to see the full table of results with the status of each test case.
